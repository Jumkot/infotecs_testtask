# infotecs_testtask
Тестовое задание для стажировки в ИнфоТеКС (2026)
## Содержимое проекта
Проект содержит:
1. Динамическую библиотеку для записи текстовых логирующих сообщений в журнал;
2. Набор тестов для библиотеки;
3. Многопоточное приложение, использующее вышеописанную библиотеку.  
## Требования
+ Linux
+ g++
+ C++17
+ GNU make  
## Сборка
Команды указаны для корневого каталога репозитория.  
Сборка библиотеки и приложения:
```
make
```
Сборка и запуск тестов библиотеки:
```
make test
```
Запуск приложения с параметрами по умолчанию (demo.log, WARNING):
```
make run
```
Запуск приложения с произвольными параметрами:
```
make run FILE=<имя файла> LEVEL=<уровень важности>
```
Очистка (удаление каталога сборки с объектными и исполняемыми файлами + результатов тестирования):
```
make clean
```  
## Возможности
### Библиотека
+ Предоставляет три уровня важности сообщений:
  * INFO
  * WARNING
  * ERROR
+ Фильтрацию по заданному уровню важности. Сообщения с уровнем ниже заданного по умолчанию не будут вноситься в журнал;
+ Возможность изменения уровня важности по умолчанию;
+ Запись логирующих сообщений в указанный пользователем файл в формате:
```
[2026-08-25 23:20:52] [WARNING]: check 1
```  
### Приложение
Использует очередь запросов и два потока:
+ Принимающий (input). Получает от пользователя запросы, потокобезопасно кладёт их в очередь и уведомляет пишущий поток об изменении состояния очереди;
+ Пишущий (writer). Под защитой мьютекса извлекает запросы из очереди, в зависимости от его типа производит запись в журнал либо меняет уровень важности по умолчанию на полученный. Для ожидания появления запросов используется std::condition_variable, чтобы пишущий поток не выполнял активный опрос очереди.
Запросы делятся на два вида:
1) логирующее сообщение, которое нужно записать в журнал. Может не иметь указанного уровня важности, тогда будет указан уровень важности по умолчанию;
2) запрос на смену уровня важности по умолчанию.  
## Команды
Сообщение с указанным уровнем важности:
```  
<LOGGING LEVEL> <Logging message>
```
Сообщение без указания уровня важности:
```  
<Logging message>
```
Смена уровня важности по умолчанию:
```  
<LOGGING LEVEL>
```
Завершение работы приложения:
```  
exit
```
## Примеры работы
При запуске с параметрами FILE=demo.log и LEVEL=WARNING следующее сообщение обработается корректно, но в журнал записано не будет:
```
INFO one two
```
Если сменить уровень важности по умолчанию на INFO, такие сообщения начнут записываться:
```
WARNING it's warning = write
INFO one two
INFO
Logging level was changed to INFO
INFO one one
```
Результат в журнале:
```
[2026-08-26 15:47:43] [WARNING]: it's warning = write
[2026-08-26 15:47:54] [INFO   ]: one one
```
При смене уровня на ERROR сообщения с уровнем ниже не будут записываться (то есть с любым LEVEL, кроме ERROR):
```
INFO still here
ERROR
Logging level was changed to ERROR
WARNING only error  
ERROR only error 
INFO not error
just error
```
Результат в журнале:
```
[2026-08-26 15:50:06] [INFO   ]: still here
[2026-08-26 15:50:37] [ERROR  ]: only error
[2026-08-26 15:53:29] [ERROR  ]: just error
```
